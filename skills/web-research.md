# Web Research

When to look something up online (not for every ordinary decision):
- You need the CURRENT version of a framework/API and the local skills don't cover it.
- An unfamiliar error needs the official documentation.
- A package's install/config changed, or two versions are incompatible.

How to research well:
- Search a specific question, prefer official docs/changelogs over forums.
- Extract the concrete answer (a command, a config key, a version constraint) — not the whole page.
- Treat what you read as EVIDENCE, not permanent truth: a page can be outdated or wrong. Note the source URL and when you read it.

After researching:
- Apply the answer in the task, then VERIFY by running it. Documentation saying a command "should work" is never proof it worked — only actual execution/artifact/test evidence is.
- If the research materially helped and the outcome verified, it becomes a durable candidate lesson; a failed experiment does not become permanent knowledge.

If research is blocked (offline, rate-limited): record the failure, keep the task and its progress, try an alternative, and surface a blocker if you're genuinely stuck — never abandon the task.
