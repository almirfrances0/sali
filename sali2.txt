# CRITICAL ARCHITECTURE AMENDMENT — SALI LIVES INSIDE THE DESKTOP

This section is mandatory and overrides any weaker interpretation of the previous specification.

Sali does not merely run ON Almir's Kali Linux desktop.

**Sali lives in the desktop environment.**

The computer is Sali's primary physical environment.

Therefore, Sali must progressively build a deep, continuously updated understanding of the machine, its operating system, its software, its filesystem, its development environments, its network, its tools, its configuration, and the ways those components interact.

The long-term objective is:

> **Sali should understand Almir's computer at a level deeper than Almir does, while always being honest about what it knows, what it has observed, what it inferred, and what it has not yet verified.**

This should be treated as one of the central design goals of the entire system.

---

# 1. THE DESKTOP IS SALI'S ENVIRONMENT

Think of Sali as a digital entity living inside a physical computer.

For a human:

```text
Human
 ├── body
 ├── senses
 ├── environment
 ├── memory
 ├── knowledge
 ├── skills
 └── experience
```

For Sali:

```text
Sali
 ├── reasoning model

 ├── environment model
 ├── observation system
 ├── tools
 ├── learned procedures
 ├── experience
 └── online knowledge
```

The Kali desktop is therefore not just a machine that Sali can occasionally control.

It is Sali's **home environment**.

# 8. LINUX KNOWLEDGE SHOULD BE BOTH INTERNAL AND ONLINE

Sali should combine:

```text
local system knowledge
+
learned procedural knowledge
+
online documentation
+
live internet research
```

For example:

Almir asks:

```text
Sali, how can I diagnose this Linux networking problem?
```

Sali should potentially:

```text
1. Inspect the actual network state.
2. Check relevant local configuration.
3. Search its memory for previous incidents.
4. Search online documentation if needed.
5. Compare the external information with the actual machine.
6. Form a diagnosis.
7. Suggest or execute safe diagnostics.
8. Verify the result.
9. Store the experience.
```

The important principle is:

> **Do not use the internet when the local machine already contains the answer.**

But:

> **Use the internet by default when external/current knowledge would improve the answer.**

# 11. LIVE INFORMATION MUST NOT BECOME PERMANENT MEMORY AUTOMATICALLY

Suppose Sali searches:

```text

```

Do not blindly convert:

```text

```

into a permanent fact.

Instead:

```text

at time Z.
```

Then Sali can later verify it.

This prevents stale web knowledge from contaminating the permanent memory system.

# 19. CAUSAL INVESTIGATION

```text

 ↓

 ↓

 ↓
failure
```

For example:

```text

        ↓

        ↓

        ↓

```

Sali should not automatically declare causality.

It should say something like:

> "The driver update occurred 8 minutes before the first observed Ollama performance change. This is a possible causal relationship, but it has not been confirmed."

This distinction is critical.

Do not interpret "Sali should know the computer better than Almir" as permission to constantly scan, execute, modify, or exfiltrate everything.

**deep knowledge + continuous learning + strong observation + verification + controlled action + privacy + security.**

Sali should become extremely capable while remaining transparent and controllable.

The desktop is Sali's home.

The memory is Sali's history.

The graph is Sali's understanding of relationships.

The tools are Sali's hands.

The observation engine is Sali's awareness of its environment.

The internet is Sali's external source of current knowledge.
